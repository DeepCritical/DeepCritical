# OpenMM Molecular Dynamics Tool (`openmm_md`)

The `openmm_md` tool integrates OpenMM, a high-performance molecular dynamics simulation toolkit, into the DeepCritical PRIME ecosystem. It allows agents to run short, targeted MD simulations to analyze protein stability, ligand binding, and other dynamic molecular properties.

## Purpose

The primary goal of this tool is to provide rapid, interpretable feedback for hypothesis testing within an agent-driven workflow. It is designed for tasks such as:

-   Relaxing structures predicted by AlphaFold2 or ESMFold.
-   Assessing the stability of a protein mutant.
-   Performing a sanity check on a ligand's binding pose from a docking tool.

The tool is **not** intended for long, production-grade research simulations.

## Installation

Due to the complexity of its dependencies, especially for GPU acceleration, it is **highly recommended** to install OpenMM in a Conda or Mamba environment.

### Recommended Mamba Setup

```bash
# Create a new environment
mamba create -n deepcritical-md python=3.11 -c conda-forge openmm openmmforcefields

# Activate the environment
mamba activate deepcritical-md

# Install DeepCritical in editable mode
pip install -e .
```

### Optional Pip Installation

For development and CPU-only testing, you can install the necessary dependencies via a `pip` optional extra. This is a convenience layer and assumes a compatible environment.

```bash
pip install -e ".[md]"
```

## Configuration

The tool is configured via Hydra. Default simulation parameters are located in `configs/simulation/openmm_md.yaml`. Global settings can be adjusted in `configs/config.yaml` under the `md` section.

### Example `config.yaml` snippet:

```yaml
# Molecular Dynamics Configuration
md:
  enabled: true
  backend: "openmm"
  max_steps_default: 50000
  max_steps_hard_limit: 500000
  allowed_platforms: ["CPU", "CUDA", "OpenCL"]
```

## Usage

The `openmm_md` tool is typically used as part of a larger workflow generated by the PRIME planner. An agent might chain it after a structure prediction or docking step.

### Example Workflow

1.  `uniprot_query`: Fetch a protein sequence.
2.  `alphafold2`: Predict the structure of the protein.
3.  `openmm_md`: Run a short simulation to relax the predicted structure and assess its stability.

### Input Schema

-   `structure` (pdb): The input protein structure in PDB format.
-   `ligand` (sdf, optional): An optional ligand file in SDF format.
-   `simulation_config` (dict, optional): A dictionary to override default simulation parameters (e.g., `n_steps`, `temperature_K`).

### Output Schema

-   `summary` (dict): A dictionary containing a summary of the simulation results, including average potential energy, RMSD, and other metrics.
-   `trajectory_path` (string): The file path to the simulation trajectory (DCD format).
-   `checkpoint_path` (string): The file path to the simulation checkpoint file.
